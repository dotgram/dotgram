Since 0.2.0. docs/syntax.md is the language, docs/diagnostics.md every message by its identifier; docs/status.md says what this version does and does not do yet.

BREAKING CHANGES, and what to do about each. Regenerate the parser to take any of them.

- Renamed attributes and options; the old names are gone from source, with no obsolete aliases. Rename them where you wrote them:
  [GramOptions(Suffix = "X", ...)]     -> [GramParserVariant("X", ...)]   (the name is the required argument)
  [Gram(..., Suffix = "X")]            -> [Gram(..., Name = "X")]
  [Gram] IncludedAs                    -> DefaultAlias
  [GramInclude] As                     -> Alias
  BufferedInput                        -> BufferedText
  SpanCaptures                         -> UseSpanCaptures
  BufferSize                           -> InitialBufferSize
  MaxRetained                          -> MaxBufferedInputLength
  Stacks                               -> MaxExtraStacks
  PartSize                             -> TargetMethodPartSize
  PerCall                              -> UsePerCallLocations
  Portable                             -> ExportGrammar
  GramCarrier.Tape                     -> GramCarrier.Deferred
  A project still written with an old name gets GRAM0012 (error) at it, saying what it is called now, beside C#'s own "could not be found"; where it dropped an alias, the names the alias reached are not also reported as missing. The dotgram tool's --option says the same.
  [Gram] and [GramParserVariant] now derive from an abstract GramReadingAttribute that holds the options they share. UsePerCallLocations is on [GramParserVariant] only, and Source, DefaultAlias and the settable Name on [Gram] only: an option that meant nothing on one of them can no longer be written there. ExportGrammar not set means what Portable unset meant: the grammar is exported where the class and every class around it are public. A grammar is still included from an assembly built by 0.2, whose attributes carry the old names; that reading of the old names goes in 0.4.
- LocationType: a located value is now told through the interface, ((ILocated)made).Locate(…) as a constrained call, so an explicit implementation of Locate works and a struct is told in place. A class named as LocationType goes on working, told through the class. GRAM0011 (error) refuses a LocationType that is neither an interface nor a class declaring Locate(int at, int length), or the three-argument form with UsePerCallLocations, where a build used to fail with CS1061 in generated code.
- [GramSource], [GramLanguageDescriptor], [GramToolingGuard] and [GramToolingExternal] are hidden from IntelliSense (EditorBrowsable(Never)); the first two are written by the generator, the tooling two are experimental and may change in any release.
- The default carrier. GramCarrier.Auto now compiles every grammar it can with the immediate carrier, where it used to only where no construction could run for an abandoned reading. Constructions (=>) then run as their alternative is read, also for alternatives the parse abandons: a factory with side effects, or one that throws, behaves differently, and an exception thrown there escapes the Try methods. In a grammar with a context, constructions run interleaved with guards, switch selectors and external recognizers, so what is accepted and what is built can differ. Accepted parses no longer walk a record at the end, which makes them faster (the expression language's accepted text, by 16 to 51% against 0.2.0 on the release benchmark, about 40% on most) and the code smaller; refused input is slower and allocates more. New warning GRAM5016 names a grammar where the deferred carrier (GramCarrier.Deferred, Tape before) is the safer choice (a context shared between constructions and guards or recognizers; refusal memory quadratic in the input), and GRAM5012 (information) names the other reasons. To keep the old behaviour, set Carrier = GramCarrier.Deferred; naming either carrier silences both. GRAM5015 is no longer reported, and GRAM5007 warns only where Carrier = Immediate was named.
- Ignore-case literals ('x'i, "text"i) mean one thing everywhere: a character matches itself and its simple upper and lower case as Unicode 16.0 gives them, and a case partner on the other side of ASCII is not taken. 's'i no longer accepts U+017F, 'μ'i no longer accepts the micro sign U+00B5, 'σ'i no longer accepts final sigma ς. The generated parser no longer depends on the casing tables of the machine that built it. To accept such a character, write it as an alternative of its own.
- \p{…} reads Unicode 16.0's general categories on every runtime, from a table the generator carries, rather than asking the runtime. On .NET Framework and .NET 8 and 9 a character assigned or recategorised since their tables (U+1C89, a letter in 16.0) is read as 16.0 says; on .NET 10 nothing changes. A parser built in Visual Studio now reads categories as one built with the .NET SDK.
- New warnings, which break a build with warnings as errors until the grammar is changed: GRAM4043, a rule spelled from single characters where trivia is not empty (Std.Digit+ & ('.' & Std.Digit+)? reads "1 . 5" as a number) - join its parts with ~, declare it where trivia = none, or name trivia in it where a space is meant; GRAM4051, trivia not written in braces beside a class that reads the same characters (trivia = ' '* beside Field = [^ ','|'\n']+, whose refusals are exponential) - write trivia = { … }; GRAM4042, a binding power that cannot reach its operand; GRAM4052, a repetition that can read one run of text in two ways ((X+)*, ('a' | 'a' & 'a')+), so that a refused input is read again for every way of cutting the run - put braces around the repetition or what it repeats, or rewrite it so that every text has one reading (docs/diagnostics.md).
- New build warnings GRAM6001-GRAM6005, about what a [GramClassify] names, which also break a build with warnings as errors: before, only the Visual Studio extension showed them, in the editor. The build reports them for every [Gram] host with [GramClassify], at the same places and with the same binder as the extension, which now shows the build's rather than its own. A suppression written against them goes on working; fix the target, or suppress the identifier.
- New errors for grammars 0.2.0 compiled and then read wrongly: GRAM3011, GRAM4040 and GRAM4041 for with expressions and calls into a namespace with a rebinding header that were read under the wrong rule (docs/syntax.md section 5.1); GRAM4036, a with inside an instance of a parameterized rule made only under another rebinding, which was dropped; GRAM4038, a recover inside a lookahead; GRAM4044 and GRAM4045, a recover the reading could not carry (inside a rule the lexer reads; a guard or value crossing an inner recover); GRAM4046, a located rule (LocationType) whose value is a Nullable of a struct; GRAM4039, a capture in a step of a left-recursive rule with no =>; GRAM2005, a binding power above 9999; GRAM3022, two imports at one scope that both declare trivia. Each message says what to write instead.
- A range with nothing after its .. is refused, GRAM2014: ['a'..] was read as ['a']. Write the upper bound, or ['a'] for one character.
- Type arguments after a rule, a parameter or a capture are refused, GRAM2016: B<int> was read as B. Only a C# name, written with @, is generic.
- The names the generated parser gives parameters of its own (parserSource, parserStarts, parserLengths, parserReading, parserLocating, parserWhole) are reserved beside the supplied ones: a capture, or a rule's parameter of any kind, recognizer or value, with one of them or with a supplied name is refused, GRAM4012, where it was accepted (L(parserReading) = parserReading, A = parserReading: 'a'); C# in a grammar that names one of the parser's own is GRAM4053. Rename it.
- A rule typed by a rule the grammar generates a type for, B : A where A captures, gives back A's generated type, where it gave back the text it matched as a string: B : A = x: 'b' => x returned "b" and is now GRAM4056, the string not being an A. Hand back an A (=> A(…), the operand that produces one, or captures filling it by name), or type the rule : string.
- A switch's parse errors have identifiers of their own, where all were GRAM2003: GRAM2020, something in its braces that is not a case, a default or a body, or a label that is not a whole number or a string; GRAM2021, a label or default written twice; GRAM2022, numbers and strings mixed; GRAM2023, no label, or a label with no body. A case-insensitive character in an element set is GRAM2015, also GRAM2003 before. A suppression of GRAM2003 written for one of them follows the new number.
- Rebindings stack: where several reach one call, the one written closer to where the reading starts applies on top of the others and rebinds what they put in place ((X with (D = Y)) with (Y = P) reads P, as X with (D = Y, Y = P)); a caller's with or namespace header applies on top of the header of a namespace it calls into.
- GRAM0010: a project that compiles C# below 8 (the default for netstandard2.0 and .NET Framework) and has a [Gram] is told once to set <LangVersion>8.0</LangVersion> or later, and no parser is generated. It used to get a wall of compiler errors. The attributes file every referencing project gets is now C# 7.3, so a project with no [Gram] builds at any version.
- Names. GRAM5018 refuses a name that would be written twice into the generated class (a publication called Match or Failure, parse Q as TryParseT beside parse T, two rules that are written alike once their namespaces are joined with _). GRAM1012 refuses a name in a grammar that contains _DotGram. The class's own helper types and pool members now carry _DotGram in their names (Lines_DotGram, Parser_DotGram, …), and a rule named like a member the class writes takes Value after its name. Code that named a generated helper type by its old name follows the new one. Generated helper members with _DotGram in their name are never public: a tagged lexer scanner (ExpressionParser.Lex_DotGram_Tag92 and the like) is no longer emitted as public, nor is Scan (below).
- Binding powers (<< and >>): after an operand read at strength k, the operator loop takes only operators weaker than k. A grouping the strengths exclude, which a when in an operator step used to accept (1+2*3 as (1+2)*3), is refused. A when or lookahead after the right operand no longer hides it from its strength. A grammar read over tokens with no when in an operator step (T-SQL, SQL-92, the expression language) is generated as before.
- Text captures and lookaheads. A text capture of a repetition that may take no turn ('a'{0,2}) is "" where it took none, not null; only ? is an option. A captured lookahead at a rule that builds a value (n: ?=Number with Number : @int) holds that value, as section 3.4 says, not the text it saw.
- Refusal positions. A literal of two or more characters the input ends inside is refused as NoMatch at the first character that does not fit it, and as Starved at the end of the input only where every character there agrees: T = "/*" & ';' refuses "/x" as NoMatch at 1 and "/" as Starved at 1, where both were Starved at 0. The same for a rule read as one scan, over a string as over a reader. A refusal's message now names that place.
- Reader forms. A parse read from a TextReader or a sequence of lines now reads what the same parse reads over a string, and a rule a reader cannot read the same way gets no reader overload, with GRAM5001 saying why: a value collected inside a part that is not a rule call, a part that holds a repetition marked recover (Group = '[' & Row* recover ';' & ']' & eol), a recovery that synchronizes on a recognizer of the host, a choice of literals that can end in two places (("a" | "ab") & "b"), a bounded repetition that can begin what follows it (A? & A+). To keep a reader overload, give the part a rule of its own; otherwise read from a string.
- Trivia is looked up in the namespace chain first, then in its imports, nearest scope first, wherever the using stands. A using at the top of a namespace block used to bring in no trivia.
- The engine's step trace for generator work is compiled where the build defines DOTGRAM_STEPS; it was DOTGRAM_TRACE, which now means nothing.
- The names a trace build declares (GramTrace, GramRead, GramWhy, GramTraceLog, GramProfile, Tracing) are reserved in every build, traced or not, so that a project that traces its Debug build alone compiles one grammar to the same names in both. A publication called one of them is now GRAM5018 in every build, and a rule whose type would take one is given the name with Value after it (a rule Tracing builds a TracingValue). Rename the publication with as; code that named such a rule's type follows the new name.
- GramRead.Forwards(rule), which no sink read and no document described, is no longer generated, nor the table behind it. What a forwarding rule did is told as before: as a frame, an Enter and an Exit where the rule was called.
- The constructor of a rule's generated result type (a rule with captures and no : @T) is internal. Its parameters are the captures in the order the grammar writes them, so swapping two captures of one type silently swapped what a caller in another assembly passed. Code beside the grammar still builds it; a value to be built elsewhere is a type of the host's own, named with : @T.
- A rule's generated type is named alike in every reading of a host ([GramParserVariant("...")]): against the host and the classes of all its readings, where each reading used to name it against its own class alone. A rule Url in a host Url builds Url.UrlValue in every reading; Url.Traced.Url is now Url.Traced.UrlValue. A publication named after a reading's class (parse Body as Traced beside a reading Traced), which wrote a method and a class of one name, is GRAM5018, and a rule of that name builds a type with Value after it. Code that named such a type in a second reading follows the new name.
- SourceSpan is internal unless a public signature the generator writes names it (a public publication whose value is a span, a property of a rule's generated type); it was public wherever it was generated, a recover or a parserSpan being enough. It is now a readonly partial struct: a host whose own public API hands one out declares public partial struct SourceSpan { } in the host class, and the generated part takes that accessibility.
- Scan, the scanner of a grammar read over tokens, is internal. The kind it gave is the grammar's own numbering of its tokens, which no constant names and which changes with the grammar. Migration: a host that wants token boundaries writes a method of its own, under another name, that calls Scan.
- The forms read from a position, TryParseX(input, at), TryParseX(input, at, length) and their bool forms with ref int at, are written only for a parse whose directive says positional: positional parse X, internal positional parse X. They used to be written for every parse read by methods or by the engine and for none lowered to a flat method, so they came and went with what the optimizer chose. Migration: write positional before parse (after the access) where the forms are called. A flat publication that asks for them keeps its flat whole parse and gets a second entry for them. positional on a find or with yield is GRAM2012, the words before the verb out of order or repeated GRAM2013, positional in a grammar that names eos GRAM4055 (docs/syntax.md sections 6 and 6.3).
- A host with several readings ([GramParserVariant("...")]) has SourceSpan, Match<T>, Outcome and ParserInput<T> written once, in a file of its own (Host.gram-shared.g.cs), each only where at least one reading needs it; the first reading's file used to write all four whatever the grammar asked for. A traced or buffered reading added beside a plain one no longer adds a public SourceSpan or ParserInput<T> to the host. As before, a host with one reading keeps these types in that reading's class: [Gram(..., Name = "Fast")] alone answers with Host.Fast.Match<T>, and a second reading moves it to Host.Match<T>.
- Std.Integer, Std.Long, Std.Decimal and Std.Double: a number too wide for its type is now a refusal instead of an exception. Std.Integer on 2147483648 threw OverflowException from ParseX and from TryParseX alike; it is now refused (TryParseX returns false, ParseX throws the FormatException every refusal throws). The same holds for Long and Decimal, and for a Double that overflows to infinity (1e309); a Double that underflows to zero is still read. A grammar that caught OverflowException should check the refusal instead; one that wants its own message declares the rule.
- The runs of the standard library are atomic: Std.Digits, Std.HexDigits, Std.Blank, Std.Spacing, Std.Identifier and the text of Std.LineComment read to the end of what they recognize and never hand a character back. A grammar that relied on one giving characters back (Std.Digits & '5' reading 15) now refuses it; write the repetition in the grammar for that. Beside non-empty trivia a run is read one way instead of as many ways as it is long, which removes the backtracking GRAM4051 warns about.

NEW

- Every diagnostic has a title of its own, the "What it says" of docs/diagnostics.md, where most used to be titled with their identifier, and a help link to its row of that file at this version's tag. The file gains a Severity column, which is the severity the build reports each identifier with; one table in the generator decides it.
- Bindings and back-references: $q: X binds the text X matched, $q matches that text again, X{#q} repeats X by its length - for constructs closed by the text that opened them (Lua long brackets, raw strings, heredocs, Markdown fences). Read over characters, through a reader and a stream; refused over tokens (GRAM4035). docs/syntax.md section 3.5.1; GRAM1011, GRAM2010, GRAM3021, GRAM4032-GRAM4035.
- A trace build: Trace = true on [Gram] or [GramParserVariant], or the build property DotGramTrace, compiles a parser that reports what it reads to a sink set with Tracing(sink). Three sinks come with it: GramWhy says why the last call was refused, GramTraceLog writes an indented log, GramProfile counts entries, failures and time per rule. A trace build answers what the parser answers; without the option nothing of it is generated. Every position it tells or hands back is a long, counted from the beginning of the input, as Match.Position is. docs/syntax.md section 6.9.
- eos, the end of a segment: a grammar that names it reads a sequence of segments (lines), from a sequence or a TextReader, as the segments are asked for wherever a record fits one segment. GRAM4047-GRAM4050 say what such a grammar refuses. The feeds of docs/feeds.md and the README end their records with eos.
- Std.Nested(open, close), a pair that holds others to any depth: Std.Nested("/*", "*/") reads /* a /* b */ c */ whole, by a counter in braced trivia and in tokens. GRAM4037 refuses arguments a counter cannot tell apart.
- ConstructionsMayThrow = true on [Gram] or [GramParserVariant]: on the immediate carrier, what a construction throws on a reading the parse gives up is held and thrown only where the deferred carrier would have thrown it, so a grammar keeps the immediate carrier's speed and the deferred carrier's answers, exceptions included. Off by default; it costs every construction a handler. docs/syntax.md section 7.5.
- UsePerCallLocations = true on a [GramParserVariant] that names a LocationType: the grammar is compiled once, and the nested class it names holds the same published methods with locations on. DotGram.Sql's TransactSqlParser.Located is built this way. docs/syntax.md section 6.8.
- A command-line build keeps the parsers it compiled in the compiler server, so the next build after an edit to C# alone does not compile the grammars again; DotGramNoCache turns it off. docs/syntax.md section 6.8.
- DotGramPositionalFollow, an experimental build property for the forms that begin at a position (docs/syntax.md section 6.8).
- The memo of successes: an ordered choice whose alternatives read a nested instance of their own recursion before either can be refused (a bracket read as a value and then as a condition, a row against a bracketed value, a subquery read and then declined) used to read every level of a nest once per alternative, two to the depth, on accepted input. The generator now finds the shape (GRAM4054, information, at the rule, naming the alternatives and the text after which both read the same construct) and, over tokens on the immediate carrier, the reader remembers where the rules of that recursion succeed and what they built, so every level is read once; the message shows the rewrite that reads the shared text once and needs no memo (docs/syntax.md section 4.7). DOTGRAM_NO_SUCCESS_MEMO compiles a parser without it, for a comparison.
- New information GRAM5017: a construction of a publication with a reader overload changes the context, and may run a different number of times there than over a string.
- A recover factory is told where reading the bad element stopped and what would have fit there (parserExpected, parserFailureLine, parserFailureColumn, parserFailurePosition), and parserMessage says both.
- DotGram.Cli, a new .NET tool (dotnet tool install DotGram.Cli): dotnet dotgram generate writes the parsers a build would generate, for a project that then compiles them without referencing this package. docs/cli.md.

FASTER

- A run read up to a delimiter, (?!X & any)* & X, searches for where the delimiter may begin rather than trying it at every character.
- A refused input on the immediate carrier no longer builds the standing turns of a loop again on every attempt: a list of a thousand members refused after its last allocated 24 MB and now 96 KB.
- Binding powers over characters: a refused text no longer costs two to the power of its operators (the README calculator refused 1/0+1/0+… of twenty terms in two seconds; five hundred and twelve now take a tenth of a second).
- A grammar of several hundred rules read from a buffer no longer takes minutes to generate.

FIXED (each takes effect once the parser is generated again)

- A grammar included from a referenced assembly that carries it ([GramSource]) is read from the assembly, which is the grammar it was compiled from. A .gram file of the same name in the including project, a fixture or a copy, used to take its place silently; it is now left alone, and GRAM0017 (information) says so where the two differ.
- Editing a .gram file reads again only the grammars that can read that file, where it used to read every grammar of the project again.
- Generated code that did not compile: a located rule built from its own captures (CS7036); a publication named input or context (CS0149); a reader form of a recovering rule in a grammar with a context (CS7036); an external recognizer or predicate named text, p, c, value and the like (CS0149); a lambda, pattern or query in a when or => hiding a capture of the same name (CS0103); a recovery in a rule no publication reaches (CS1061, CS0649); a fold with no construction (CS1522); a struct nested in the host shadowing an imported class of its name (CS1503); a recognizer of the host met only in a recovery's synchronization (CS0103, CS0246).
- A grammar read over tokens (Lexical = true) whose terminals name context, or hold a when … is … the publications answer differently, did not compile (CS7036), nor one with UsePerCallLocations beside a terminal that binds text: the lexer and the code that builds a token's value now hand the context, the reading and the located argument on. A guard of such a terminal sees the context as the publication was handed it, since the tokens are cut before the syntax reads anything, and has to give the same answer throughout the parse; a grammar whose terminals depend on what the syntax has read is one for Lexical = false. New warning GRAM5019 names a guard that names context in a terminal whose value is built by reading its token again, where the check runs again against the context as written by then. Where that reading again refuses the token, the parser throws InvalidOperationException naming the terminal and where its token stood; it used to answer with a null value. A positional reading of such a grammar keeps its cutting of the string unless what the lexer measures reads the context (docs/syntax.md section 7.1).
- A guard that reads a captured value (when @(n < 100) after n: Num) inside a terminal of a grammar read over tokens did not compile (CS1061): the parser the lexer's terminals are read with now keeps the values built so far for such a guard, as it does for a guard of the syntax.
- The generator stopped with an exception on: a left-recursive rule that builds nothing on the immediate carrier ("A value table for 'string' was named"); a guard or a capture written in a recover's synchronization (KeyNotFoundException); wordboundary that can match nothing (now GRAM4001); a recovery's => on a repetition captured whole as text ("No value table for 'string'", now GRAM4010); a parameterized rule named without its arguments, Q = P beside P(x) (KeyNotFoundException, now GRAM4013 at the name).
- An external recognizer is looked up where the generated call stands, as the compiler binds it, rather than by every method of that name in the compilation (GRAM4015 and code that did not compile). A host recognizer that refuses inside a negative lookahead or an atomic group goes on to the group's next alternative.
- A rule's generated type named by the rule (docs/syntax.md sections 3.7 and 4.1): => Pair(right, left) builds the type generated for Pair, where it was written as a call of a type (CS1955); a rule declared Swapped : Pair takes that type, where it was declared to give back a string (CS0029), and gets its value from its =>, from the one operand that produces a Pair, or by filling it from its captures by name; Pairs : Pair[] collects the Pairs it reads. A rule whose generated type the grammar names is kept for its type when no parse reaches it, and GRAM5018 asks for it to be renamed where its type would have to take another name.
- New error GRAM4056: a construction whose value cannot be the declared type, said on the grammar where it was a C# error in the generated file - a capture handed back whole that holds text where an array is declared (items: { Item }* => @(items) beside : @string[]), a generated type where another is declared (between the grammar's generated types, C#'s keyword types and arrays of them; a type of the host's, which may declare a conversion, is left to the C# compiler), a generated type built with the wrong number of values or from a capture that cannot be its member, or a rule's name built or taken as a type where the grammar generates none for it.
- A rule called with, recover, as, stream, bytes, and, or or is, declared on the line after an operand or a directive, was read as that operand's with or recover, the directive's as or stream, or a condition's and, or or is, and told as a broken rebinding or a missing '='. A word that begins a rule's head (an =, parameters, a type) begins that rule there, as it does everywhere else.
- Parse errors in the words of the mistake, where they used to name a token or a declaration expected, or came later in the words of a rule the generator made: GRAM2017, a second quantifier ('a'*?, 'a'+*; there are no lazy quantifiers); GRAM2014, a range outside brackets ('a'..'z'); GRAM2015, a case-insensitive bound (['a'..'z'i]); GRAM2019, a using after the first declaration.
- A worded keyword is no longer matched inside a longer word over tokens.
- A rule of a namespace with a rebinding header (namespace N with (…)), called from outside it (R = N.E), is read under the header; it used to be read as if the header had not been written, with no diagnostic.
- A repetition whose turn may match nothing only through an external recognizer no longer loops for ever; the turns up to its fewest are counted however far each moved.
- The generator no longer runs for ever on a ring of rules that lead with one another (R0 = R1, R1 = R3 | 'b', R3 = R0 & 'a'): working out what each rule begins with went round without settling, so a build or an editor never finished. Such a grammar is refused for its left recursion (GRAM4002), as it always was once read; working out what the rules begin with now notices when it comes back to where it already was, and stops there, and a grammar on which it does and that nothing else refuses would be refused with the new error GRAM4057. Every grammar that compiled before compiles to the same code.
- A guarded repetition with a most ((?!';' & any){0,2}) is held to it over a string; a negative look over a run read from a buffer reads as the string does.
- A reader, a sequence of lines or of segments no longer takes the end of the part it holds for the end of the input where a lookahead calls a rule read as one scan, nor in a choice of literals or a recovery's skip at that end. Before, a reader could accept or refuse otherwise than the string, with no error.
- A repetition marked recover inside another one's element or synchronization recovers as a rule of its own, rather than as a plain repetition.
- A guard or lookahead after the last operand of an alternative no longer hides that operand from the analyses of recursion and strength.
- A located rule (LocationType) whose value is a struct is told its location on the value it returns; with UsePerCallLocations a mutable struct no longer loses it.
- A @SourceSpan rule with => returns the span it builds, not its extent. A place past int.MaxValue characters into a streamed input throws InvalidOperationException where it would be told, rather than wrapping round.
- A refusal at a place that very many alternatives tied for kept every set they said (a repetition inside a repetition, two to the n ways of one input: gigabytes on forty characters). The list is kept up to 16384 sets; past them the message names the first 16384 and ends "among others", and a trace sink is handed GramTrace.TruncatedTies as the last set. A refusal with fewer ties reads as it did.
- The located config example (Formats/LocatedConfigExample.cs) no longer reads a line every way it can be cut, so a refused file is read in time linear in its length. It accepts what it accepted; in one corner, a key whose equals sign is on the next line after a # that holds another key, it returns the earlier of the two valid cuts.
- A reader that runs its stack low and carries the reading onto a thread of its own probes the stack again from the first entry when it comes back (ten thousand nested T-SQL CASE ended the process), and reuses one thread for every hand-off.
- The direct reader and the engine, the two ways the generator reads a grammar, give every form of a parse one outcome, position and value, as docs/syntax.md section 7.5 says; random grammars found about one in eleven answering apart. A refused negative lookahead is refused where it stands; a reading from a position is never refused before where it began; input that runs out inside a negative lookahead no longer makes the parse Starved (?!("kk") & 'z' refuses "k" as NoMatch); a rule read as one scan keeps how far an optional or repeated literal agreed; the trivia at the start of a reading from a position gives no characters back to the rule. Three refusals inside trivia still differ (the release's known issues).
- Generated code that did not compile: a lexical grammar whose trivia holds an element set beside a Std.Nested pair (trivia = { (Std.Whitespace | '#' & Std.Nested("(", ")"))* }) referred to a character table the scanner never declared, CS0103.

KNOWN ISSUES

- Over characters, a repetition that gives a turn back reads the turns before it again from the start each time, so a refused text costs the square of its length (a refused sum of 2,048 quotients in the calculator: about half a second). Bound the size of untrusted input.
- By default a parse read from a position or a window can refuse, or cut short, the rule's first reading in a few shapes (an optional or a repetition before a negative lookahead, a quoted string with doubled quotes; docs/syntax.md section 6.8). The whole forms are right. The experimental build property DotGramPositionalFollow fixes them at a cost.
- See the known issues of the release on GitHub, and docs/status.md, for the rest.
