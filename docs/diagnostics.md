# Diagnostics

Every message .Gram reports carries an identifier, so it can be looked up, suppressed, or
argued with. This is the list.

**Numbers go by the stage that raises them.** `GRAM0xxx` is the Roslyn shell — the part that
finds a grammar and hands it to the compiler; `GRAM1xxx` the lexer; `GRAM2xxx` the parser;
`GRAM3xxx` the binder, which resolves names; `GRAM4xxx` the normalizer, which lowers the
grammar and checks what it means; `GRAM5xxx` the analyses that decide what a grammar *gets*
rather than whether it is one. `GRAM6xxx` is about the tooling a grammar is annotated for, and
has a section of its own before the retired numbers.

**Severity** is what the build reports an identifier with unless the project says otherwise
(`.editorconfig`, `<NoWarn>`, `<WarningsAsErrors>`). Every row has an anchor, and a diagnostic's
help link points at its row in this file as it stood in the version that reported it.

**This file is the list, and the analyzer's release files are not.** `AnalyzerReleases.Shipped.md`
holds only what the Roslyn shell declares as rules of its own, which is `GRAM0xxx`. Everything a
grammar is told is reported through a descriptor made from its identifier as the message arrives,
so Roslyn never sees those rules to track them — and a suppression or a severity is written
against the identifier either way.

**A retired number is not reused.** A suppression written against the old meaning would
silently acquire a new one. The retired numbers are listed at the end.

**Where a message points.** A grammar in a `.gram` file is underlined in that file. A grammar
written into the `[Gram("…")]` attribute is underlined inside the string literal, at the
character the grammar's own position maps to. A grammar inherited from a base class, or included with
`[GramInclude]`, is underlined where it was written, in its own file — see syntax.md §6.7.

## GRAM0xxx — finding the grammar

| Id | Severity | What it says | What to do |
| --- | --- | --- | --- |
| <a id="gram0001"></a>`GRAM0001` | Error | The generator itself failed. | A defect in .Gram, not in the grammar. The message names the stage and carries the exception; please report it. |
| <a id="gram0002"></a>`GRAM0002` | Error | A class hosting a grammar must be `partial`. | Add `partial` to the class the `[Gram]` attribute is on. A nested host needs every enclosing class to be `partial` as well. |
| <a id="gram0003"></a>`GRAM0003` | Error | No grammar file for a `[Gram]` class. | Add the `.gram` file, or add it to the project as `<AdditionalFiles Include="…" />`. |
| <a id="gram0004"></a>`GRAM0004` | Error | More than one grammar file matches. | Two additional files answer to the same name. Name one of them in the attribute: `[Gram("Feed.gram")]`. |
| <a id="gram0005"></a>`GRAM0005` | Error | The name a grammar is included under is not an identifier. | `[Gram(DefaultAlias = "…")]` names the namespace an including grammar reaches this one through, so it has to be one identifier. |
| <a id="gram0006"></a>`GRAM0006` | Error | Two readings of one grammar want the same scope. | The `[Gram]` and every `[GramParserVariant]` on a class is a compilation of its own and needs a scope of its own: the `[Gram]` goes in the class itself, and every `[GramParserVariant]` names a nested class, its one argument. |
| <a id="gram0007"></a>`GRAM0007` | Error | The name a grammar is compiled under is not an identifier. | `[GramParserVariant("…")]`, and `[Gram(Name = "…")]`, name a nested class, and a class is named by an identifier; a `[GramParserVariant]` whose name is empty is told the same. |
| <a id="gram0008"></a>`GRAM0008` | Error | Two grammars are included under one name. | An included grammar is wrapped in a namespace named after it, which is what keeps two grammars' rules apart: `Sql92.Identifier` and `Lex.Identifier` are different names. Two under one name are one namespace, and their rules do collide — give all but one an `Alias` of its own. |
| <a id="gram0009"></a>`GRAM0009` | Error | A buffer option is not positive. | `[Gram(MaxBufferedInputLength = …)]` is the most a buffered parse may hold and `InitialBufferSize` the capacity it starts with, so either is at least 1. Leave it out for no limit, or give a call its own `maxRetained`. |
| <a id="gram0010"></a>`GRAM0010` | Error | The generated parser needs C# 8 or later. | The project compiles an earlier version — C# 7.3 is the default for `netstandard2.0` and .NET Framework — and no parser is generated below C# 8. Set `<LangVersion>8.0</LangVersion>` or later in the project. Reported once, at the first `[Gram]`; a project with none builds at any version.
| <a id="gram0011"></a>`GRAM0011` | Error | The location type declares no `Locate`. | `LocationType` names an interface, or a class, whose implementors are told where they were written, through `void Locate(int at, int length)` — with `UsePerCallLocations`, `void Locate(int at, int length, int gapStart)` (syntax.md §6.8). Name such a type, or declare the method on the one named; an interface's is called through the interface, so an explicit implementation serves. Said on the attribute that names the type: for a per-call reading, its `[GramParserVariant]`. |
| <a id="gram0017"></a>`GRAM0017` | Info | A local grammar file is not the grammar a referenced assembly carries. | **Information.** A class from a referenced assembly that carries its grammar (`[GramSource]`) is always included with that grammar, which is the one the assembly was compiled from; a `.gram` file of the same name in this project — a fixture, a copy — is not read in its place, and this says so where the two differ. Nothing to do unless the local file was meant to be the grammar: then rename the file, or include a class of this project that reads it. |

| <a id="gram2004"></a>`GRAM2004` | Error | Expected a name. | |
| <a id="gram2005"></a>`GRAM2005` | Error | A binding power is a whole number from 0 to 9999. | `<< 2`, `>> 3` (§4.3.1). |
| <a id="gram2006"></a>`GRAM2006` | Error | A namespace header's rebindings need `with`. | `namespace Name with (A = B) { … }` (§5.1). |
| <a id="gram2007"></a>`GRAM2007` | Error | A publication of anything but a rule's name needs `as`. | `parse` and `find` name the method after the rule; an expression has no name to make one from, so give it one: `parse X & Y as Both`. |
| <a id="gram2008"></a>`GRAM2008` | Error | A named yield publication places a result type before `yield`. | Write the element contract after `yield : @T` (§6). |
| <a id="gram2009"></a>`GRAM2009` | Error | A condition after `when` whose operand is not followed by `is`. | A `when` is either a C# guard, written `when @(…)` and asked while the parser runs, or a condition about the grammar, written `when A is B` and answered while it is built. Both sides of that question are written out, so an operand with no `is` after it is neither one thing nor the other. |
| <a id="gram2010"></a>`GRAM2010` | Error | A length `#q` stands only inside count braces. | `#q` is the length of the text bound to `$q`, and a length is a count: `X{#q}`, `X{#q,}`, `X{2,#q}`. To match the bound text itself, write `$q`. |
| <a id="gram2011"></a>`GRAM2011` | Error | Something stands more than 128 levels deep inside others: groups, braces, lookaheads, captures, bindings, a call's arguments, a condition's parentheses, a C# type's arguments, namespaces. | One level each, so a group is two, itself and what it holds: sixty-three groups inside each other are read, the sixty-fourth is not. The parser and every stage after it take a rule apart by recursion over its tree, so how deep one rule may nest is bounded here, and what went too deep is said once and read past. Name the inner part as a rule of its own and call it: a chain of rules calling each other may be as long as you like. |
| <a id="gram2012"></a>`GRAM2012` | Error | `positional` on a `find` or on a `parse … yield`. | Neither has forms read from a position: a `find` looks at every position of the input itself, and a `yield` has no `Try` form to begin where it is told (§6.3). Drop the word. |
| <a id="gram2013"></a>`GRAM2013` | Error | The words before a directive's verb are out of order, one is written twice, or one stands after a directive on its line. | The access comes first and `positional` after it, at the start of the directive's line: `internal positional parse X` (§6). A directive has one access, and each word is written once. Written after a directive, as `stream` is, the word would be read as the next directive's. |
| <a id="gram2014"></a>`GRAM2014` | Error | A character range is malformed: nothing after its `..` (`['a'..]`), a string as its bound (`['a'.."z"]`), or written outside brackets (`'a'..'z'`). | A range is an element of a set and has a character at both ends: `['a'..'z']`. A set of one character is `['a']`. `['a'..]` used to be read as `['a']` without a word. |
| <a id="gram2015"></a>`GRAM2015` | Error | A case-insensitive character is an element of a set or a bound of a range: `['a'i]`, `['a'..'z'i]`. | A set holds characters as they are written. Write both cases, `['a'..'z' \| 'A'..'Z']`, or a choice of literals, `'a'i \| 'b'i`. |
| <a id="gram2016"></a>`GRAM2016` | Error | Type arguments after a name of the grammar: `B<int>`. | A rule, a parameter or a capture takes no type arguments; only a C# name is generic, and it is written with `@`: `@B<int>`. They used to be read and dropped without a word. |
| <a id="gram2017"></a>`GRAM2017` | Error | A second quantifier on one operand: `'a'*?`, `'a'+*`, `'a'{2}?`. | An operand takes one quantifier, and a repetition is always greedy: there are no lazy or possessive forms. To repeat a repetition, group it, `('a'*)?`; to keep a repetition from giving back what it took, make it atomic, `{ 'a'* }` (§3.3). |
| <a id="gram2019"></a>`GRAM2019` | Error | A `using` or `@using` after the first declaration of its file or namespace block. | Imports stand at the head of the file or of the block, before every rule, namespace and directive: move it up. |
| <a id="gram2020"></a>`GRAM2020` | Error | A `switch`'s braces hold something that is not a `case` label, a `default` or a body; or a label is not a whole number or a string, or is a number too large for a `long` (a `ulong` if it is not negative). | `switch @(kind) { case 0: Text case -1: none case "s": Text default: none }` (§3.6). What follows a label the switch cannot read is read past, to the brace that closes it. |
| <a id="gram2021"></a>`GRAM2021` | Error | A `switch` label, or its `default`, is written twice. | Each value selects one body. Labels that share a body are written one after another: `case 0: case 1: Text`. |
| <a id="gram2022"></a>`GRAM2022` | Error | A `switch`'s labels are numbers and strings both. | The value they are compared with has one type: all whole numbers or all strings. |
| <a id="gram2023"></a>`GRAM2023` | Error | A `switch` has no case, or a label has no body after its `:`. | A label is followed by the grammar its value selects; `none` is a body that matches nothing. |

## GRAM4xxx — what the grammar means

| Id | Severity | What it says | What to do |
| --- | --- | --- | --- |
| <a id="gram4001"></a>`GRAM4001` | Error | The body of a repetition can match without consuming input. | The repetition would not terminate. A `word` over a `wordboundary` that can match nothing is a repetition of it, and is said at the boundary's declaration (§4.6). |
| <a id="gram4002"></a>`GRAM4002` | Error | Left recursion the rewrite cannot take. | Direct left recursion is built, and so is an indirect one through rules that only forward. What is refused is an intermediary that does something of its own, a rule with no alternative to start from, and an alternative recursive on both sides (§4.3). |
| <a id="gram4003"></a>`GRAM4003` | Error | `trivia` must accept empty input. | It is inserted between every pair of operands, and a required match would demand whitespace everywhere (§4.5). |
| <a id="gram4005"></a>`GRAM4005` | Error | A name in an element set is not a rule. | |
| <a id="gram4006"></a>`GRAM4006` | Error | A capture inside a lookahead, or one read there. | What a lookahead records is dropped whether it matched or not. Capture the lookahead itself: `?=X` produces X's value (§3.4). A `when` inside a lookahead may not yet read a capture made before it, `c: X & ?=(when @(c.Length > 0))`: the lookahead is a reading of its own and is not handed it. A guard reads nothing and needs no lookahead around it — write it beside the lookahead, and `?!(when @(g))` as `when @(!(g))`. |
| <a id="gram4007"></a>`GRAM4007` | Error | One name is captured twice with different types. | A member has one type; give the two captures the same one, or different names (§7.3). A fold step (§4.3) that collects a name another alternative holds once is the same case: one side is a sequence, the other a scalar. |
| <a id="gram4008"></a>`GRAM4008` | Error | A `=>` is not on an alternative, or a rule that builds does not say what type. | A `=>` builds the rule's value, so it belongs at the end of an alternative, and the rule needs `: @T` to say what it builds. |
| <a id="gram4009"></a>`GRAM4009` | Error | An alternative is recursive and states no strength while its siblings do. | A rule uses one convention or the other — levels as rules, or `<<` and `>>` on every recursive alternative (§4.3.1). |
| <a id="gram4010"></a>`GRAM4010` | Error | A recovery's `=>` has no sequence to put the rejected element in. | The repetition collects text rather than values. Give the repeated rule a capture of its own, or drop the `=>` and report out of band (§8.2). Said too where the elements build values, no capture holds each one, and the alternative they stand in has no `=>` of the author's — the rule is its text (`: @string`, or no type) or its extent (`: @SourceSpan`), or a sequence they do not join: the rejection would be dropped with them. Declare the rule a sequence of them (`: T[]`) or capture each element. An alternative with its own `=>` says what it builds and is not refused. A rule whose every alternative forwards another rule's value — `Line : @T = v: Item => @(v) \| v: Remark => @(v)` — builds a value, and is read as one here. A repetition of values captured whole, `rows: (Row* recover ';' => …)`, is its text too (§7.3), and is refused the same way: capture each element, `rows: Row* recover ';' => …`. |
| <a id="gram4011"></a>`GRAM4011` | Error | A rule's declared type is neither a C# type nor a rule in view. | §4.1 case 3 takes the value of a rule named here; a C# type is written with `@`. |
| <a id="gram4012"></a>`GRAM4012` | Error | A capture or a rule's parameter takes one of the supplied names, or one of the names the generated parser gives parameters of its own: `parserSource`, `parserStarts`, `parserLengths`, `parserReading`, `parserLocating`, `parserWhole`. | Every name the parser supplies to a `=>` or a `when`, and every one it keeps for itself, begins with `parser`, which is what that prefix is for (§7.3, §8.2). A capture or a parameter of one of them would be declared beside the generated one. Rename it. |
| <a id="gram4013"></a>`GRAM4013` | Error | A call of a parameterized rule that cannot be built, or a value where a piece of grammar goes. | The message says which: a value standing where a piece of grammar goes — a value is allowed where a value is expected, a count, an argument of `@Method`, inside `@(…)`, so drop its type to make it a recognizer; a call with the wrong number of arguments, said at the call; a parameterized rule named without any, `Std.Nested` for `Std.Nested("/*", "*/")`, which is no rule until a call gives it its arguments — in a publication too, which names a rule and passes nothing, so a rule that calls it is published instead; a value parameter passed something that is not a value; a count naming a parameter that was given no number; or a call that would specialize for ever (§4.2). |
| <a id="gram4014"></a>`GRAM4014` | Error | A rebinding's replacement produces an incompatible result. | A rule that reads the replaced one into a type of its own — a declared C# type, a sequence, a constructor — expects the replaced rule's type; so does one that reads a copy of a rule following it (`R : B`) under a `with` or a publication's `with`, whatever its action then does with the value. The message names that reader, the rule it reads and both types. Declare the reader as `: Rule` of the rule it reads, so that its type follows the replacement (§4.1 case 3), or replace with a rule whose result converts to the expected type (§5.1). |
| <a id="gram4015"></a>`GRAM4015` | Error | An external recognizer has more than one value-returning overload with different `T`. | Bare `@Name` cannot say which is meant; give it one such overload, or none (§7.1). |
| <a id="gram4016"></a>`GRAM4016` | Warning | Two alternatives begin with the same operand, and that operand leads back to the rule. | **A warning, and a choice rather than a mistake.** Ordered choice reads the operand once for each alternative, so the reading doubles at every level of nesting. Written as one alternative with the rest of the longer one optional it is read once — but that is a different grammar wherever the operand can give back. See §4.5 on saying a lexeme is read once. |
| <a id="gram4017"></a>`GRAM4017` | Error | Two substitutions each need the other applied first: two rules each contain a `with` that reaches the other, a namespace's header reaches a `with` that calls back into the namespace from outside it, or two namespaces' headers each reach, from outside, a rule the other rebinds. | Neither can be specialized against the other already specialized. Give one of them the rebinding the other was going to apply, or write the substitution as a `namespace Name with (…)` block around both; for a header, write the rebinding inside the namespace or on a publication (§5.1). |
| <a id="gram4018"></a>`GRAM4018` | Warning | A rule nothing reaches. | A warning: nothing published names it, no rule the grammar reads calls it, no element set drew its items from it, and no rebinding puts it in place of one — so nothing it says is ever read. Publish it, call it, or delete it. Said only about a grammar that is otherwise sound, because a declaration whose syntax did not come out can leave any rule below it unreached; and never about `trivia`, `wordboundary` or the rest of the built-in rules, which are configuration rather than rules a grammar calls; nor about the standard library (`Std`), which every grammar has whole and few call much of. A grammar that publishes nothing is not asked at all. |
| <a id="gram4019"></a>`GRAM4019` | Error | `word` in a grammar that never said what continues a word. | `word` is a run of whatever `wordboundary` matches (§4.6), so without one it is a run of nothing: the rule matches everywhere and consumes nothing. Declare the boundary, or say the shape that was actually meant. |
| <a id="gram4020"></a>`GRAM4020` | Error | A `when … is …` somewhere other than beside the operands of an alternative. | The condition is answered while the parser is built, and what it decides is whether an alternative is in this parser at all — so an alternative is what it has to be able to delete. Inside a group, a repetition or a capture there is nothing for it to remove. Move it out to the operands of the alternative it belongs to. |
| <a id="gram4021"></a>`GRAM4021` | Error | A `when … is …` whose sides are not two listable sets of strings. | `is` asks whether two recognizers have a string in common. That is decidable, but this compiler answers it only where each side is a literal, a choice of them, or a rule that is one — which is what a domain and a range are. An error, and the build fails with it: the alternative is kept as though the condition held rather than guessed at, since deciding it either way silently changes what the parser reads. Write each side as one of those. |
| <a id="gram4022"></a>`GRAM4022` | Info | Every alternative of a rule is ruled out by a condition in this parser. | Information, not a warning: a construct removed from a dialect has to be removable, and this is what removing one looks like — a grammar written per version does it in nearly every parser it publishes. The rule becomes one that cannot match, so a caller of it fails where the construct is written and nowhere else. Worth a second look only where no removal was meant. |
| <a id="gram4023"></a>`GRAM4023` | Error | A grammar published in more than 64 readings. | A `with` that substitutes a rule only conditions ask about makes a reading of the grammar, and the parsers of one rule share one machine told apart by the reading's number — one bit each in a word. Sixty-four is room for every version and product of a real language several times over; publish fewer, or split the grammar. |
| <a id="gram4024"></a>`GRAM4024` | Error | A `when` that leaves different C# behind in different readings. | The parsers of one rule share a machine, and a condition decides per reading whether its alternative is there. Where the C# beside it survives in two readings as two different pieces of C#, the C# would have to be told which reading it runs in, and it is not. Asked for and not given is worth a warning. The message says which it is — no trivia at all, so there is nothing to tell a token from a character; a terminal that is not a regular language; a `find`, which hunts through characters for a place to begin; a `trivia` not written in braces, the seam between tokens being skipped by the scanner braces ask for; a published rule that is no token of its own over tokens — what the seam is made of, or a helper a terminal calls; a published terminal that builds a value, which over tokens only the rules that call it read; or a terminal that builds its value from its own captures, where over tokens a terminal's value is read again only as a type it declares (`: @T` with `=>`). A terminal that binds text (§3.5.1) adds four, each naming the fix and ending "this part is read over characters": its body is not atomic, so write `{ }` around it to read it as one token; another token can match a longer text that begins like it, so keep that token from continuing the beginning, or put both in one terminal as alternatives; trivia can begin where it begins; or two such terminals have beginnings of which one begins the other's. |
| <a id="gram5005"></a>`GRAM5005` | Warning | A split grammar's syntactic half cannot be read by methods, so it runs on the shared engine. | A warning: the grammar was cut in two to be read by methods, and part of it is not. The engine reads it as the methods would — over kinds it compiles each call, and each choice and repetition of a rule not marked `?`, as if braced, so a rule's answer stands (docs/syntax.md §4) and a choice or a repetition that has matched is revisited only inside a rule marked `?` — but it is the slower rendering, and a grammar written to be read by methods is told which rule took it off them. The message names the rule and what about it the methods refused: a recovery, a stream, a `find`, a captured lookahead, a guard handed what a reader cannot hand it, or a rule called with arguments. |
| <a id="gram5007"></a>`GRAM5007` | Warning | The immediate carrier was asked for by name and is not what carries some of the grammar. | Only where `Carrier = GramCarrier.Immediate` is written: a grammar left to the generator falls back to `Deferred` in silence, and the carriers report says which of its machines did. The machines named are compiled deferred, and each is the one it would have been without the request; the rest of the grammar keeps the carrier. The message names the publications and the input forms that moved, and every reason and every rule that stands in the way: the carrier refuses a machine that recovers where a construction is not settled at its rule's end, one with a rule that is an extent collected across the turns of a repetition, one where two members gathered across turns onto the stack of one type are taken by one construction (members of alternatives with a construction each never meet, so those are carried), and one where a sequence is gathered from values of several types. The other case is a grammar nothing of which is read by methods at all, since a carrier is what a reader holds: then the whole grammar is carried deferred, and the message says why it is not read by methods. A `find` beside a `parse` is not one of these: it is a machine on the engine next to one the carrier is carrying, which is `GRAM5005`. A warning: the parser is correct, but a carrier asked for by name is a carrier somebody means to measure or to rely on, and one that quietly is not there makes every comparison against it compare the deferred carrier with itself. |
| <a id="gram5009"></a>`GRAM5009` | Info | An optional or a repetition can take what follows it, where nothing can give it back. | Information. Over characters this is settled by backtracking and the parse succeeds by the second reading, which is `GRAM5002`; over kinds a rule's answer stands (§4), so the optional takes what follows, what follows is not there any more, and the rule fails one token past what it ate. Asked only of a grammar cut in two, and only of what the optional can match in **one token** — an optional that begins like the next clause and cannot match the whole of it fails and gives nothing back. The fix is a lookahead in front of it naming what it may not take, as `?!SourceClause & Identifier` does. Where the sequence has nothing left to read, what follows is what follows the *rule*. |
| <a id="gram5011"></a>`GRAM5011` | Warning | A terminal of a split grammar is nothing but `@M`. | A warning: the lexer has no beginning to stop on, so it asks the host at the start of every token, before its own automaton. Write what the terminal begins with in front of it — `Blob = '<' & @ReadBlob` — and the automaton reads that beginning with every other token, and the host is asked only where it stands, from where it ends. The rest may be a rule instead of a method, where the grammar can say it: `Comment = '/*' & Nested`. |
| <a id="gram5012"></a>`GRAM5012` | Info | A grammar left to the generator is carried as `Immediate`, and `Deferred` would hold some of its constructions back. | Information, said only where `Carrier` is not written. The generator carries every grammar it can with the immediate carrier: every construction runs where its alternative is read, and the walk the deferred carrier runs at the end is not there. Where a rule it builds is read for a derivation that may be given up, or can be read again after it has answered, its constructions can run for text the parser then reads another way, or reads a second time — in a grammar with no context and no recovery a constant number of times, at most two attempts for each enclosing loop that gives back: the reading made again for the message, and every attempt after a turn has been given back a second time until one stands, build nothing but what a guard names. With a context, the reading for the message builds again; where a way back is taken in a loop that cannot read unbuilt — a context, a recovery, a rule whose own guard asks for its value so far — the warning is `GRAM5016` instead. Where a construction writes `context` and nothing that runs during recognition reads it, the message says so first. A construction that only builds does not mind; one that can throw, or has side effects, behaves differently there than deferred: an exception it throws escapes the publication (§7.5), unless the grammar says `ConstructionsMayThrow = true`, which holds it and throws it only where the deferred carrier would have. The message names that option where the grammar does not set it; a grammar whose constructions only throw, and have no other effect, can set it and keep the immediate carrier. The message names the rules. `Carrier = GramCarrier.Deferred` holds every construction back until a parse has accepted (§3.7); `Carrier = GramCarrier.Immediate` says the author has checked, and silences this and every reason found later. Nothing is said where nothing is held back, where the immediate carrier refuses the grammar, or where `GRAM5016` is said. |
| <a id="gram5014"></a>`GRAM5014` | Info | A buffered form is read by the engine where its string form is read by methods. | Information. A publication read by methods over a string is read by methods over a `TextReader` or a `Stream` too, except where a rule it reaches can reach itself: a reading that deep goes on in another thread with the whole input, and a buffer cannot hand that over. The parse is correct either way; this says why the two forms are two renderings. |
| <a id="gram5013"></a>`GRAM5013` | Info | Whether a refused input is read again over a context put back as it was. | Information. A parse reads first without recording what it would say if refused, and reads a refused input again to say it (§7.7). Over a context the reading writes into, the second reading has to begin where the first began: where the context's type has an instance `Mark()` and a `Rollback` taking what `Mark()` returns, the parser calls them and says so; where it has not, every input is read once, recording, and the message says the pair is what would change that. |
| <a id="gram5016"></a>`GRAM5016` | Warning | A grammar left to the generator is carried as `Immediate`, and `Deferred` would be safer. | A warning, said only where `Carrier` is not written, for the two reasons that can change more than whether a construction runs twice. One: constructions that name `context` share it with a hook that runs during recognition — a `when`, a `switch` selector, or an external recognizer handed the context — and a rule they are in is read for a derivation that may not stand or can be read again. Carried immediately a construction runs as its alternative is read, interleaved with those hooks, rather than after the parse has accepted, so a guard or a recognizer can see what a construction wrote, and a construction that reads `context` sees it as it stands at that point: what the grammar accepts and the values it builds can both differ from the deferred carrier's (§7.7). Two: a refused input can allocate memory quadratic in its length, because what a rule that builds has read is built again each time a way back is taken — a list once a turn given back: the reader reads unbuilt after a loop's second give-back, and does not where the grammar has a context or a recovery, or where a rule's own guard asks for its value so far. Said of every loop that asks for another reading of a rule that builds, in such a grammar: whether the input can take a way back once a turn is not something the generator can see. For untrusted input keep it deferred. The message names the rules. `Carrier = GramCarrier.Deferred` holds every construction back until a parse has accepted; `Carrier = GramCarrier.Immediate` says the author has checked, and silences this and every reason found later. |
| <a id="gram5017"></a>`GRAM5017` | Info | A construction of a publication read from a reader or lines changes the context. | **Information.** A construction that assigns to, compound-assigns or increments a member of `context` (`context.Rows++`) is reachable from a publication that has an overload over a reader or a sequence of lines. A streamed reading may run a construction a different number of times than a reading of a string does (§6.3), so what it leaves in the context may differ. Said once for the publication, at it. Syntactic and best-effort: comments are skipped and parentheses, `!`, `?.` and `@` in the member are seen, but a string that spells such a change is taken for one, and a change made by calling a method of the context, or through a local that holds it, is not seen. Read the context in a construction, or do the work in the one that builds the result. |
| <a id="gram5018"></a>`GRAM5018` | Error | A name would be written twice into the generated class. | An error, said where the author wrote the name. A publication, or the `Try` of a `parse`, named after a class of a reading of the host (`[GramParserVariant("Name")]`), or `Match`, `Outcome`, `SourceSpan`, `ParserInput`, `OnRecovered`, `OnHandingOff`, `OnTakingOver`, `Scan` (in a grammar read over tokens only), `DefaultBufferSize`, `DefaultMaxRetained`, `Failure`, `ParserEntry`, one of the fields of the pools (`_spareParser`, …), or one of the names a trace build declares (`GramTrace`, `GramRead`, `GramWhy`, `GramTraceLog`, `GramProfile`, `Tracing`; in every build, traced or not), after the class itself, or written by another publication (§6); two rules that are written alike once their namespaces are joined with `_` (`A.B` and `A_B`), or one whose joined name would hold `_DotGram` (`DotGram_B` in namespace `A`); two captures of one rule that become one property (`a` and `A`, or `r` and `rValue` in a rule called `R`) (§7.3). Rename one of them. And a part of `SourceSpan` declared in the class of a reading of a host with several readings, which share one span in the host: declare the part in the host (§6.2). The type a rule's value takes is given another name by the generator where it would take one of the names above or another rule's type, and is not this error — except where the grammar names that type by its rule, as `Swapped : Pair` or `=> Pair(a, b)` do (§3.7, §4.1): a name the grammar writes has to be the type's, so a rule whose type would be renamed is this error, and is renamed by its author. That is the whole list, and it is closed: every other name the class writes has `_DotGram` in it, and every one made from a name of the grammar's is its kind, `_DotGram_` and that name, with nothing after it (§6), so it is never a name an author can write and never another such name. |
| <a id="gram5019"></a>`GRAM5019` | Warning | A guard that names `context` is read again where a terminal's value is built. | A warning, at the terminal, in a grammar read over tokens (`Lexical = true`). The lexer reads the token under the context as the publication was handed it; a terminal whose value is built by reading its token again runs its guards again then, against the context as the parse has written it by that time. Where the context has changed in between, the value can be another alternative's, with nothing to say so, or the reading again refuses the token and the parse throws an `InvalidOperationException` naming the terminal and where it stood (§7.1). A risk and not a proven error: a guard that reads configuration holding for the whole parse is safe, and the warning can be suppressed for it; one that reads what the syntax writes needs the grammar read over characters, without `Lexical = true`. Not said of a terminal whose value is its token's own text, which is not read again. |

## GRAM6xxx — the tooling a grammar is annotated for

`GRAM600x` are about the classifications a `[GramClassify]` attribute declares for a grammar's
language. The build reports them, underlined inside the attribute's target, and Visual Studio
shows the build's; the editor holds the targets to the grammar with the same binder and does
not report them a second time. `GRAM61xx` are the Visual Studio extension's alone, reported in
the editor about a string written in that language at an embedded DSL site; a build never shows
them.

| Id | Severity | What it says | What to do |
| --- | --- | --- | --- |
| <a id="gram6001"></a>`GRAM6001` | Warning | A classification target is neither `Rule` nor `Rule.capture`. | A warning, underlined inside the attribute's target. Name a rule, or a rule and one of its captures, separated by one dot. |
| <a id="gram6002"></a>`GRAM6002` | Warning | The grammar rule a classification target names was not found. | A warning. Name a rule the grammar declares. |
| <a id="gram6003"></a>`GRAM6003` | Warning | The grammar rule a classification target names is ambiguous. | A warning: more than one rule answers to the name. Name the one meant. |
| <a id="gram6004"></a>`GRAM6004` | Warning | The capture a classification target names was not found in its rule. | A warning. Name a capture the rule declares. |
| <a id="gram6005"></a>`GRAM6005` | Warning | A classification target is specified more than once. | A warning. Keep one `[GramClassify]` per target. |
| <a id="gram6101"></a>`GRAM6101` | Error | The text of an embedded DSL site does not match its language. | An error, underlined at the position where recognition failed. The message names what was expected there. |
