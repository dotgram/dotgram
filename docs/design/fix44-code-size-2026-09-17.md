# FIX 4.4 example generated code size

Analyzed the existing generated artifact from the user's Finance checkout build,
not a regenerated approximation. The file contains 71,560,015 UTF-8 bytes plus a
three-byte BOM, matching the supplied build log (60 normalized rules, 4,089.28 ms
generation). This is the example Fix44Grammar, not the library FixGrammar.

Roslyn syntax spans partition leaf member declarations without counting their
containing types twice. Full spans include associated whitespace and comments.
The remaining 2,752 bytes belong to surrounding declarations and file trivia.

| Category | Bytes | Share |
| --- | ---: | ---: |
| Recognizers, including helper methods | 62,176,558 | 86.89% |
| Materializers | 5,766,276 | 8.06% |
| Construction factories | 1,994,620 | 2.79% |
| Fields | 1,548,080 | 2.16% |
| Other members | 71,729 | 0.10% |

Four publications produce twelve large recognizer methods: ordinary characters,
buffered characters and buffered bytes for normal/log separators and Parse/Read.
Each large method is approximately 5.05-5.25 MB. Each has a corresponding roughly
0.48 MB materializer. Sharing these requires preserving streaming/yield lifetime,
recovery, diagnostics and input representation; they are not assumed interchangeable.

The ordinary Fields recognizer contains 912 SequenceEqual literal comparisons and
7,031 trace call sites attributed to KnownField_ValueText. Inspection shows repeated
choice/atomic/capture/repeat bookkeeping around tag literals and value recognition.
The prefix selection switch has 880 sections. These are generated source counts,
not runtime execution counts. They point to expanded per-field control flow as a
major size concern, not merely the cardinality of the character alphabet.

All prefix table fields together occupy 696,716 bytes (0.97% of the file).
State dispatch fields occupy 580,804 bytes; expected-diagnostic fields 254,265 bytes.
These figures do not bound every possible benefit of a table-driven recognizer:
replacing expanded control flow is a different and potentially larger change than
compressing existing table columns.

## Next experiments

1. Preserve this grammar as a stress fixture; do not simplify it to improve results.
2. Investigate sharing Parse/Read recognizers within each input representation.
3. Identify repeated per-field state actions suitable for compact data tables.
4. Measure alphabet equivalence classes separately, including character-mode
   machines: this fixture has Lexical=false and Direct=false.
5. Keep direct emitted methods as the small-grammar baseline. Compare runtime,
   cold initialization, allocations, generated bytes and compilation cost before
   selecting a table representation.

No production code or grammar changes were made. This is source-size analysis,
not a runtime or compiler benchmark. Raw totals and artifact hash are in
benchmarks/results/fix44-code-size-2026-09-17.json.
