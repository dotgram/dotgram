Examples of what benchmarks/Run-Bdn.ps1 writes (run.txt), from 2026-09-21. None of them carries a quotable number: they are here for their SHAPE.
- run-probe-scriptdom-tree.txt and run-probe-sqlstandard-generated.txt: the two pricing probes taken before the real SQL window (assembly built from 102df6e0 in the sql worktree). Marked PRICING PROBE in the note: their numbers are not to be quoted; what was taken from them is the wall time of a case (about 21 s for a ScriptDom case, about 32 s for a SqlStandard case) and that BDN's own build of the generated project (60-70 s) is inside a first run. Every worker was read back at 0xFFFF / High; the coverage line says BDN executed 9 (6) workers and 9 (6) were read.
- run-refused-affinity-255.txt: a deliberately wrong run (BDN was given `--affinity 255`, decimal, so its workers ran on 0xFF): the script read the first worker at 0xFF, stopped the run and reported FAILED, exit code 4.
- run-probe-fix-oursparse.txt: the pricing probe of the FIX comparison (finance-41's qfcompare, built outside the repository against d476b533; -Commit names it): ten cases (both schemas, five shapes) in 253 seconds, the workers read at 11:06:56, 11:07:18, 11:07:46, 11:08:04, 11:08:30, 11:08:56, 11:09:16, 11:09:44, 11:10:05, 11:10:31: 18-28 seconds between two workers, about 24 s a case, and NO visible BDN build at the start (the first worker was read 9 s after the announcement: the generated project was reused). An unpinned restore and compile of another session ran for 22 seconds from the announcement (11:06:47-11:07:09; the architect); the first case took 22 s, inside the range of the others: no outlier. Marked PRICING PROBE; its numbers are not quoted.
- The quiet check of Run-Bdn.ps1 (added after that overlap): an idle machine read 1.7-2.8% of the 32 logical processors over twelve samples of three seconds (a light keeper at 0.3 core, the sessions' own processes at about 0.2), so the refusal is above 6% of the machine or any build tool (dotnet, MSBuild, csc, the compiler servers, git) above 0.15 core; tested both ways (a pass that printed "2.1%, busiest LEDKeeper2 0.323", and a refusal, exit 5, with a build running beside it: "csc (pid 43836) 1.464 cores", 6.4%).
