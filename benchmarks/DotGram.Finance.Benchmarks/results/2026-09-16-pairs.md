# Explicit FIX pairs: performance comparison, 2026-09-16

## Result

The pair refactoring does not improve throughput. The short byte-stream order
regresses from 8.012 to 10.474 microseconds (31% more time). Mean times for character
and string orders rise 12% and 7%; group means rise 1-7%. Small timing differences
are not established by this ShortRun, especially where confidence intervals are
wide. Byte raw-data time is unchanged at approximately 230 microseconds.

Allocations increase for ordinary fields too: the group workload grows from
686.09 to 780.23 KiB on byte streams, 783.66 to 877.76 KiB on character readers,
and 282.51 to 329.57 KiB on strings. These increases are approximately 14%, 12%
and 17%, respectively.

The implementation adds Unit classification guards, a FixFieldUnit result for
ordinary fields as well as pairs, and an intermediate unit array plus flattening
for non-yield parsing. Those are concrete additional operations and storage;
this measurement does not attribute exact timing shares to them or establish
whether JIT stack layout changed. Removing KnownTag and simplifying the grammar
did not by itself make the generated parser faster. No parser changes or rollback
were made as part of this measurement.

## Method

Baseline is the saved Release net10.0 assembly for the grammar at b18b78b,
also used by the initialization investigation at 4a54508. Candidate is 2512de2,
with explicit length/data pairs. Both execute equivalent public calls in the
same BenchmarkDotNet process through compiled delegates. No reflection or input
generation occurs during timing. Stream/reader construction and complete
field enumeration are included. Message semantics are excluded.

Before timing, the harness verifies identical field case names, serialized public
values and locations for 186 message fixtures plus all three workloads, in string,
character-reader and byte-stream forms. All 18 benchmarks completed successfully.
The candidate already passed 3596 Finance tests in the preceding implementation
run; this measurement rebuilt the benchmark project, not the parser.

Assembly SHA-256:

- Baseline: `6EAFDC62459D3CA301F651F7F3B015F9D12901A87A3BFE47054245595551CB38`
- Candidate: `4893E157141C428D303F6A96216AEE8BCEDD0B11403949B30A0E0ABDE1EAE819`

Three warmups and three measurement iterations, normal runtime tiering. Error in
the table is the 99.9% confidence interval half-width. Method names are retained
from the reusable harness: Previous is the baseline and Simplified is 2512de2.

## Reproduction

Save the baseline DLL outside build output before rebuilding the benchmark project.

```powershell
$env:DOTGRAM_FIX_BASELINE = 'T:/TEMP/fix-pairs-baseline/DotGram.Finance.dll'
$env:DOTGRAM_FIX_FIXTURES = 'P:/dotgram.WorkTrees/finance/tests/DotGram.Finance.Tests/Fixtures.json'
dotnet run --project benchmarks/DotGram.Finance.Benchmarks -c Release --no-build -- --filter '*FixGrammarComparisonBenchmarks*' --job short --inProcess --artifacts T:/TEMP/fix-pairs-comparison
```
