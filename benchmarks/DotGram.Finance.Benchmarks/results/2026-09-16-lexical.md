# FIX Lexical mode probe, 2026-09-16

## Result

Adding `Lexical = true` to the current FixGrammar host does not switch this grammar
to tokens. The compiler refuses lexical splitting when any publication uses yield
and emits GRAM5004. This repository treats that warning as an error, so the
experimental Release net10.0 build fails.

Diagnostic:

```text
GRAM5004: This grammar is compiled over characters rather than tokens:
Yield publications currently use character recognition rather than token-kind input..
The parser is the one it would have been without the request.
```

Despite the diagnostic, the emitted FixGrammar.g.cs is byte-for-byte identical to
the saved baseline. Both files have SHA-256:

`C0AC0DBF61659E61852DBD0368322004B03B6FF4B1910D029D4A940D457BE9C2`

No timing comparison was run: measuring this fallback would compare the same
parser, not lexical versus scannerless recognition. There is no measured lexical
speedup or slowdown to report. The experimental attribute was removed; production
source is unchanged from dd9c582.

## Evidence and remaining requirements

`GramCompiler.Cut` checks `PublishKind.Yield` before attempting `LexicalSplit.Of`
and returns null with the diagnostic above. Current FIX publications include two
yield directives for lazy field enumeration. The compiler also requires a trivia
boundary for lexical splitting; the FIX grammar has none. The current skill and
syntax documentation describe token parsing as memory-only, without reader
variants. Removing yield alone is not evidence that this grammar would tokenize.

A meaningful experiment therefore needs either a separate in-memory token grammar
with equivalent binary-field behavior, or compiler support for lexical yield and
buffered input. Neither was implemented by this flag-only probe.

## Reproduction

At dd9c582, save the generated FixGrammar.g.cs, add `Lexical = true` to the Gram
attribute in FixGrammar.cs, then run:

```powershell
dotnet build src/DotGram.Finance -c Release -f net10.0 --no-restore -p:BuildProjectReferences=false
```

Compare the saved and resulting generated files, and restore the attribute.
The baseline net10.0 assembly SHA-256 was:

`9EE8AF9433D63C0F3B10277665E8E52C52DDD75CFC4A64460E8E24DA3D6F87C3`
